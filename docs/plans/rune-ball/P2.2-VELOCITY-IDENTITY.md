# Rune Ball — P2.2 Velocity Identity & Rebound Readability

## Why this slice exists

The P2.1 phone playtest confirmed that rebound utility improved chase flow, but two issues remained:

1. repeated swipes still increased normal speed, which diluted the value of the rebound speed state;
2. rebound presentation was too similar to normal travel, so the gameplay state change was difficult to perceive.

The same playtest found that target respawn placement already felt natural, but a lightweight materialize beat would make the field feel more alive without adding persistent UI.

## Product decision

Velocity now has a simple authored language:

```text
Swipe      = direction control at cruise velocity
Rebound    = temporary high-speed re-entry state
Overdrive  = later escalation tier, intentionally not implemented here
```

Repeated swipe input must not stack speed. This protects directional input from becoming a spam-for-DPS mechanic and preserves room for later escalation systems.

## P2.2 implementation

### Cruise velocity

- normal travel is centered on a stable 360 px/s cruise speed;
- directional swipe strongly redirects the ball but does not add cumulative velocity;
- if future interactions reduce base speed below cruise, a valid swipe may restore cruise speed;
- normal authored ceiling remains separate from the rebound ceiling.

### Rebound velocity

- wall bounce keeps deterministic reflection and forward-cone assist from P2.1;
- rebound applies a temporary ~24% speed tier above cruise;
- rebound remains bounded below 470 px/s;
- the bonus decays over the existing 0.72 second window;
- swiping during rebound can replace direction immediately without stacking another speed bonus.

### Rebound signature beat

The rebound state is communicated in-world rather than with another HUD element:

1. short ball compression at wall contact;
2. rapid directional stretch away from the wall;
3. white/cyan directional launch streak and expanding contact ring;
4. longer, brighter continuous rebound trail;
5. stronger ball glow during the temporary speed state;
6. return to the normal trail automatically as the bonus expires.

The effect uses the existing cyan/white motion language. Magenta remains associated with destructive payoff so rebound does not visually compete with Crystal Break.

### Target spawn transient

Respawn events receive a ~220 ms materialize treatment:

- contracting violet/cyan glyph ring;
- scale-up from a compact silhouette;
- brief settle overshoot;
- opacity resolves to the existing target treatment.

This is contextual world feedback only. No new HUD, badge, progress bar, or spawn marker is added.

## Scope guard

P2.2 does not add:

- Rune recognition or Rune charge;
- Flow or Overdrive;
- audio;
- score/combo rule changes;
- target count changes;
- new deployment architecture;
- meta progression.

## Playtest gate

Test on phone for roughly 30–45 seconds and answer only these questions:

1. Does repeated normal swiping still feel responsive and enjoyable even though it no longer stacks speed?
2. Does wall contact now read immediately as a distinct launch / high-speed state?
3. Is rebound faster enough to feel valuable without becoming hard to read?
4. Can swipe still override rebound direction instantly?
5. Does target materialization make respawn feel more alive without distracting from the ball and active targets?
6. Did Crystal / Armored / Combo behavior remain intact?

If 1–4 pass and 5 does not introduce noise, P2 is closed and the main roadmap proceeds to P3 — Rune Gesture Gate.
